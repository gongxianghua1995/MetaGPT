# MetaGPT SWE Pro：提前检查与保留返修窗口

## 本次改动

保持 MetaGPT Leader + 上游 mini-swe-agent Engineer + MetaGPT Reviewer 架构，以及每题 25 分钟、同一模型、各角色单次 16,384 输出 tokens 的配置。修复目标是过晚落代码、过晚发现运行时错误、最终审查后无返修时间。

- `swe_budget.py`：新增可选调度 `--first-edit-fraction 0.4 --repair-seconds 120`。本轮显式使用该配置；因为冒烟没有改善结果，结束后恢复调度默认值 `first_edit_fraction=0.6`、`repair_seconds=0`，不将三次审查方案推广为默认。预算校验包含第三次审查及最后修正时间。
- `swe_protocol.py`：首轮修订提前截止，给第二次审查和最后修正留时间；第三次提交前仍保留最后的 Reviewer 预算。25 分钟配置的最晚时间点为：10 分钟首次提交、17 分钟主要修订截止、20 分钟第二次审查结束、22 分钟最终修正截止、25 分钟整题截止。提前提交或审查提前结束时会产生额外可用时间；不强制等待。
- `swe_mini_engineer.py`：第三轮以 `repair_only` 标识启动上游 mini，带入原始公共任务、已确认文件路径和最新具体反馈。
- `swe_execution.py` / `swe_mini_worker.py`：添加阶段提醒。最迟在阶段前三分钟提示落实一个可运行修改；每次工作树变化使验证状态失效，提醒优先加载模块并调用改动入口。编译成功不代表导入和运行成功。失败或零测试仍保持待验证状态。此逻辑是上游 mini 的环境反馈，不是新的本地 agent，也没有硬编码任何任务的修复答案。
- Reviewer 优先反馈最多三个具体阻塞问题；末次审查距整题截止保留 15 秒收尾余量，减少角色请求与全局取消撞在同一时刻的风险。各角色输出 token 上限不变。

## 验证与实验约束

76 项离线回归通过，记录 `/tmp/metagpt_pro23_tests.log`。新增覆盖包括三次审查的预算计算、第二次审查后的真实返修、第三轮 mini 请求的 `repair_only` 和剩余时间、修改后的验证失效，以及旧调度通过 `repair_seconds=0` 兼容。mini Python 3.11 环境编译检查通过。

复跑上一轮相同的 OpenLibrary `322d` 和 Ansible `bec27`，按域并行；输入哈希、代码快照和启动参数保存在 `workspace/pro23_schedule_smoke_20260922`。生成/评估容器均 `network=none`，生成仅保留基线 Git 对象。没有把历史 patch、隐藏测试或具体失败答案输入生成 agent。

这是两例定向诊断，无法单凭通过率证明框架整体效果。执行阶段提醒属于提示约束，提前提交和预留返修的截止时间属于实际调度约束，需要分别看真实轨迹。

## 轨迹与原因

### OpenLibrary：提前发现运行时缺陷，但业务行为仍错

- 约 499 秒首次改动，600 秒首次提交；约 647 秒 Reviewer 指出新旧接口混用导致模块导入 NameError。第二轮修复了该错误，并成功加载模块和调用基础接口。
- 1,020 秒第二次提交；Reviewer 指出 `scripts/solr_updater.py` 仍导入已删除的 `CommitRequest`。
- 约 1,173 秒进入最后修正，获得约 **147 秒**，确实删除了这处过时导入并检查编译/模块加载。这证明新增窗口产生了真实修改。
- 1,320 秒第三次提交；约 1,467 秒最终审查以 inconclusive 收尾，没有伪装成批准。
- 正式 `test_delete` / `test_redirects` 失败原因是 `EditionSolrUpdater.update_key` 额外执行 `state.deletes.append(ekey.replace('/books/', '/works/'))`。例如删除 `/books/OL23M` 时多出 `/works/OL23M`，重定向时也多出对应 work key。**这次与 Pro20/21 的网络请求异常不是同一个原因**。
- 审查注意力主要落在接口导入和旧测试收集问题，没有验证删除结果是否只包含公共需求要求的 key。修正窗口可用，但优先级和验证内容仍不充分。

### Ansible：更早审查没有带来更早实现

- 600 秒首轮提交无有效源码 diff，Reviewer 直接退回。部分改写命令成功退出但没有改变仓库；命令执行成功不等于产生实现。
- 首个有效修改约 850 秒，与上轮约 838 秒相当；1,020 秒第二次提交。
- 约 1,101 秒 Reviewer 确认旧测试 24/24 通过，要求进一步核对角色错误路径与缺失元数据行为；第三轮获得约 **219 秒**。
- 第三轮重新读取多个文件，没有新修改或新检查证据。到 1,320 秒，重复提交保护以 `unchanged patch and verification evidence; no duplicate review` 收尾，没有再消耗一次无意义审查。
- 正式失败仍为两个 `_build_summary(role, collection, meta, argspec)` 调用的参数数量 TypeError，以及 `I(italic)` 输出单引号而非反引号。两个摘要用例仍未执行到内容断言，不可描述成仅占位文案错误。
- 新窗口没有补齐需求。仅靠提示“尽早编辑”和“只修具体问题”仍不能阻止反复阅读；新增角色边界还会引入上下文重建开销。

## 保留与默认配置决定

- 保留可选三次审查调度、返修标识、修改后验证提醒，以及最终审查收尾余量。
- **调度默认恢复为 0.6 / 0 秒**，本次三次审查实验需要显式传入 `--first-edit-fraction 0.4 --repair-seconds 120`。这仅恢复调度默认，不声称完整回滚其他改动。
- 冒烟期间源码哈希一直匹配；上述默认值调整发生在两题正式评估结束后。实验目录 `source_at_run` 是真实运行版本，当前源码已包含恢复默认的修改。
- 恢复默认后重跑全部 **76 项回归通过**，记录 `/tmp/metagpt_pro23_final_tests.log`。最终默认值调整未再另跑一次付费模型实验；本轮真实冒烟始终使用显式的 0.4 / 120 配置。

## 后续重点

本次不支持单纯加时或增加审查轮数。更有针对性的方向是：

1. 跨轮延续 mini 的有效工作上下文，或保留已读代码与未完成修改的结构化记录，减少重读。当前路径证据能避免猜错目录，但不能替代工作记忆。
2. 让反馈明确指出公共需求中的一个可复现缺口、对应代码位置和最小验证，而非宽泛重述需求。第三轮应能直接执行修正及测试。
3. 对删除/重定向等行为验证结果的精确集合，不能只检查模块导入或接口存在。
4. 区分公共任务要求删除旧接口与基线测试仍引用旧接口的冲突；不应反复要求修改已有测试来获得“通过”，应保留失败说明并依据公共契约建立有断言的最小行为验证。
5. 若再次比较调度效果，应重复多次并单独统计限流干扰，不能用这两条的单次结果作全量推广依据。
