## 代码修改

### 1. API 状态与评估资格分离

`tests/metagpt/roles/di/run_swe_full_experiment.py`：

- 普通 429、RateLimit、502、连接超时仅记录 `had_transient_api_error`，不因历史日志出现过错误而停批。
- 明确认证/额度耗尽记录 `terminal_api_error`，暂停后续生成；已经生成的有效预测继续进入 eval。
- `prediction_ready` 单独记录。即使生成进程返回非零，只要已保存完整预测且具有隔离/启动记录，仍评估实际补丁。
- 一个域触发暂停后，其他在途域的已生成预测照常排入评估；后续未启动任务标记 `blocked_api`。
- eval run ID 增加输出目录摘要，避免不同批次同名叶目录相互覆盖成绩。
- API 日志仅转换为布尔状态，不把供应商异常原文写入进度文件。

`metagpt/roles/di/swe_role_tools.py`：Leader/Reviewer 对瞬时请求错误最多尝试 3 次，重试等待与 pacer 等待均包含在调用时间窗口内；硬额度/认证错误不在此层重试。mini 保留安装版本原有最多 10 次指数退避及父进程编辑期限约束，不重写其执行循环。增加角色响应 usage 记录，便于按角色统计 token。

### 2. 缺少验证时，最多补一轮定向验证

`metagpt/roles/di/reviewer.py`、`swe_protocol.py`：

- 保持 `approved / changes_requested / inconclusive` 三种审查结果。
- `inconclusive` 且缺少验证时，如果扣除最后 180 秒审查保留时间后仍有至少 60 秒，发回一次明确目标的 `CodeReviewFeedback`。
- 此轮重点是运行原有局部测试、记录真实退出码、解释已有失败；只有发现具体缺陷才改源代码。
- 已有环境阻塞、时间不足、已用过此轮验证时，保留当前补丁并结束。
- 验证补充计数与缺陷返工计数分开；保留原来的重复提交签名防护，补丁与证据都没变时不再重复审查。

### 3. 失败证据不能被自测通过覆盖

- 提交包保留命令、真实退出码、失败摘要和树摘要；新增 `current_tree`，审查过程中产生的测试证据也进入后续交接。
- 旧树上的成功测试不再满足当前提交的通过门槛。
- Reviewer 必须逐项说明失败检查的处理：公开需求明确改变旧行为、环境问题、或仍未解决，并附本地来源/公开需求证据。
- 同一命令在当前树上的成功复跑可以更新其失败状态；另一个自定义测试通过不能自动消除现有仓库测试失败。
- 公开需求与旧测试冲突时允许说明理由，不把旧测试永远视为唯一规范；也不把隐藏答案写成提示词要求。

### 冒烟中新发现并修复的证据分类缺陷

原 `check_evidence()` 只凭输出出现 `AssertionError` 就判失败，会把 `sed/grep` 读到的源码也当成失败检查。初版更严格的审查门槛放大了这一旧缺陷，使 OpenLibrary 收到重读源码、重做全盘搜索的无效“验证”目标。

初版结束后才修改 `swe_checks.py`，没有中途更改冻结运行版本：现在识别实际执行的测试程序或 `swe-check` 包装命令；普通源码读取、超时搜索不算测试结果。真实 Python 异常（包括截短的异常行）、流水线掩盖的失败、多行编辑后执行的测试继续保留。针对首轮 packet 回放，7 条非测试记录被剔除，真实 Ansible 失败检查保留。

## 复用与限制

1. 先用独立状态表示模型服务异常、预测完整性、评估成绩，再决定是否暂停队列。服务中断与补丁不正确是不同结论。
2. 把审查不确定性转成有目标且有上限的验证任务。保留最终审查时间，避免为耗满预算而无限返工。
3. 保存失败证据以及它对应的代码版本；“另一个测试通过”不是对失败的解释。
4. 用全新输出目录、唯一 eval run ID 和源码摘要保证可追溯；补评旧补丁时记录原文件/补丁 SHA-256，不混成新模型采样。
5. 输出分类是启发式；`expected_behavior` 的文字证据仍依赖 Reviewer 判断，不等于自动证明正确。小样本结果也不能证明整体能力提高。


## 结论与仍待解决的问题

调度漏评、首次不确定审查直接结束、过期成功证据、源码读取误报和空 verdict 异常已分别修复并验证。旧补丁补评找回 2 个成功结果；新增采样没有证明解决率提高，不能因此立即扩大实验并宣称框架改进有效。

剩余瓶颈有具体轨迹依据：首轮大量时间用于探索；需求与旧测试冲突时仍选择了与正式评估不兼容的行为；新需求的接口细节未被原有局部测试覆盖；自定义验证及错误测试路径未形成有效回归覆盖。后续应优先验证通用的测试发现和公开需求覆盖策略，避免把本次隐藏测试期望注入正式提示词。

进一步的调用链、交接证据及审查限制定位见 [根因分析](SWE_pro_root_cause_20260922.md)。
