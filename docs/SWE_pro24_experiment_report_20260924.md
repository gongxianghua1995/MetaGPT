## 实验配置

- 架构：MetaGPT Leader 规划 → 上游 mini-swe-agent Engineer 实现 → MetaGPT Reviewer 检查与反馈 → Engineer 按需返修；不进行框架演进或参数优化。
- 模型：`DeepSeek-V4-Flash-0731`。各角色单次最大输出 16,384 tokens，Engineer 每题最多 80 次模型请求。
- 每题生成预算 25 分钟，Leader、Reviewer 各次阶段预算最多 180 秒；调度为 `first_edit_fraction=0.6, repair_seconds=0`，未启用 Pro23 的提前三次审查方案。
- 四域并行、域内串行，最多两个独立评估并行；每题评估超时 1,800 秒，共享 API 请求最小间隔 4.2 秒。
- 输入、预算和源码哈希由 manifest 固定。运行中仅修复控制器把源码符号 `AuthenticationError` 误判为鉴权故障的问题；agent、模型、提示词和评估逻辑未因此变更。

## 异常与隔离核查

- 记录到 **625 次 RateLimitError，涉及 68 题，其中 41 题未通过或空补丁**。这是受影响范围，不代表这些失败全部由限流造成；该异常类别也包含额度耗尽返回。
- 另有 TimeoutError 90 次、CancelledError 55 次、APITimeoutError 4 次、BadGatewayError 5 次。角色或整题预算到期也会产生超时/取消，不能全部解释为服务端故障。
- 三个空补丁：Flipt `case_035`（额度耗尽），OpenLibrary `case_049`、WebClients `case_038`（轨迹存在密集限流）。9 月 23 日续跑没有再次因额度耗尽终止。
- 115 个非空补丁失败中，**13 题没有可解析测试结果**，包括编译、依赖或测试启动/收集问题。评估器在此情形也可能返回 `patch_successfully_applied=false`，不能直接按这个字段判定补丁应用失败；这些任务仍计入失败，未从分母剔除。
- 生成 **216/216** 题记录了 `network=none` 和 Git 历史隔离；实际评估 **213/213** 题记录了容器断网，3 个空补丁跳过执行评估。模型 API 由宿主调用。
- **98 个成功用例均核对了正式报告**：FAIL_TO_PASS 成功项非空，且 FAIL_TO_PASS、PASS_TO_PASS 无失败。通过数来自独立评估，不取 Reviewer 自评。断网与历史隔离核查不等于完整的答案泄漏审计；部分镜像已有环境适配差异，详见轨迹分析。

## 简要结论

当前版本已完成可复现的四域团队基线：非空补丁率 **98.61%**，正式解决率 **45.37%**，OpenLibrary 最好、Flipt 最弱。轨迹中可见 Reviewer 定位权限分支遗漏、方法放错类后，Engineer 完成真实修正并最终通过；此前的实现、交接和返修适配有实际作用。

Reviewer 判断仍不稳定：最终批准 17 题，其中 10 题正式通过；98 个正式成功中，83 个最终为 inconclusive。下一步优先处理旧失败证据消解、返修上下文重复读取和空评估输出诊断。此实验没有同预算单 mini 对照，不能据此量化团队协作的净提升；受限流影响的失败任务应另建重跑批次，保留本报告的原始成绩。
